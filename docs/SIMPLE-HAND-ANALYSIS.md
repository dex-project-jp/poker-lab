# 簡易ハンド分析（独立機能）

2026-11-05。基準main：977814441efca408f6850fb9d2fbf8382e0338c6。
長期GTO開発計画・P1条件付き抽選・認定基準・学習データは変更しない。

## モデル・精度

1対1で相手のベット全額にコールし、その後追加ベットなしでショーダウンするモデル。
自分2枚とボード3〜5枚、169クラスの相手レンジ、各クラス0〜100%の頻度を指定。
クラスをペア6、suited4、offsuit12の物理コンボへ展開し、既知カードを含むコンボを除外。
各コンボにクラス頻度を付け、残存コンボで正規化する。スート間は同一重み。
各コンボの残りデッキから未知ボードをすべて列挙（フロップ990、ターン44、リバー1通り）。
既存 `solver/hand-evaluator.js` のevaluate/compareを変更せず使用。
同じ相手コンボ数では各コンボのrunout数が等しいため、コンボ頻度で重み付けした全列挙が条件付き分布になる。
エクイティ=(勝ち重み+引き分け重み/2)/全重み。モンテカルロ近似・標本誤差なし。
頻度と金額は、入力を読み取った数値の十進表現を整数比へ変換。勝ち・引き分けの集計と判定は整数で行い、表示用の数値にだけ丸めが入る。

P=相手ベット前ポット、B=ベットとして必要エクイティ=B/(P+2B)、Call EV=q(P+2B)-B、Fold EV=0。
過去の投資額はサンクコスト。qが必要値を厳密に上回った場合だけ「この計算条件下ではコール有利」。
スタック上限・サイドポット・レーキ・将来アクション・フォールドエクイティ・ICMなし。
GTO頻度・最適アクションを計算する機能ではない。

## UI・未完了時の扱い

専用ページ、ホームと設定からのリンク。7つの52枚セレクターは他欄の使用カードを無効化し、計算側も重複を拒否。
169ハンド表はモバイルで横スクロール。複数選択、追加時頻度、各選択クラスの1%刻み編集に対応。
WorkerでUIをブロックせず全列挙。進捗表示とterminateによる中止。
カード・レンジ・額の編集で進行中Workerを終了し、以前の結果を即時削除。
空レンジ、除外後0コンボ、未入力、不正入力、計算途中、エラー、中止では結果・推奨なし。
広いフロップレンジは最大1,070,190通りの両者7枚評価となり、iPhoneでは数分以上かかる可能性あり。
近似へ自動切替しない。

厳密エクイティ差1e-12未満、列挙数一致、EV差1e-10未満を検査。
ブラウザーテストは375/390/430px、カード除外・空レンジ拒否・結果・頻度編集・入力変更・中止・横はみ出し・JSエラーを検査。

境界の回帰例：AA 9%とKK 1%、除外後にAA 1コンボ・KK 3コンボ。エクイティ25%でポット12、ベット6なら同EV。ポット11.9999/12.0001では負/正に分かれる。
