# v1.2：9人10BB・毎反復の新規配札によるMCCFR

**完全な9人卓GTOは未完成です。新しい169ハンド頻度・ハンド別EVをアプリに公開していません。** 正しく学習できる計算基盤と、最適応答候補を別配札で評価する仕組みを実装しました。学習の進行、標本誤差、実装の照合、Nash収束の証明は異なるものとして扱います。

## ゲームと情報

9人、全員10BB（強制ベット前）、SB0.5BB・BB1BB・BBアンティ1BB。Chip EV、ICM・レーキ・バウンティなし。BBの残り8BB、ライブ投入上限9BB。他席の上限10BB、SBの残り9.5BB。

52枚から非復元で9人に18枚を配り、残り34枚から未知ボード5枚を引きます。Fold済みの私札も除外。カード除外は実際の1,326コンボで処理し、方策は169クラスで共有します。既知ボードや少数の固定チケットは使いません。相手の行動は確率付きの公開履歴として扱い、到達確率にその方策を掛けます。行動履歴を無視して独立な169クラス頻度を掛け合わせているわけではありません。

未JamではFold/Jam、Jam後はFold/Call。9人までの参加・オーバーコール、サイドポット、同点、未コール返却を含みます。各人が1回だけ行動する制限ゲームです。BB未オープンはウォークで、Checkの意思決定ではありません。通常Raise、Limp、3bet、4bet、ポストフロップベットは未対応です。

情報集合は **席・自分の169クラス・公開アクション履歴**。ボード・相手の私札・配札番号を含めません。169共有方策の制限を設けており、1,326コンボそれぞれに自由な方策を許した完全ゲームの誤差保証は主張しません。内部の勝敗・カード除外はクラスのHU勝率の足し算ではなく、実カードのマルチウェイ評価です。

## 実装したMCCFR

`solver/mtt10-mccfr.js` は **chance-sampled MCCFR** です。各反復で新しい同時配札と隠れたボードをサンプリングし、その配札では全アクション木をたどります。external/outcome samplingで行動まで間引く方式ではありません。公開木は1,021ノード・510意思決定ノード・511終端。最大86,190（510×169）の情報集合です。

- 全プレイヤーの方策を反復の先頭で固定する同時更新。
- 累積後悔値は正負を保持する標準regret matching。方策を決める際に正の後悔値だけを正規化します。ノイズ付きの値を毎回0でクリップするCFR+とは区別します。既存の多人数CFR+モジュールは維持しました。
- 訪問した情報集合について、相手全員の行動による到達確率×アクションの利得差を加算します。chanceの抽選分布が対象の配札分布と同じなので、p/qの補正係数は1です。全員が1回だけ行動するため、その本人の先行行動の到達確率は1です。
- 平均方策は、自分のクラスが抽選された反復での方策の条件付き一様平均です。相手による到達確率で平均方策自体を重み付けしません。複数回の行動を追加する場合は本人のrealization reachを使う平均更新・最適応答へ拡張する必要があります。
- 固定のポット層と、配札ごとの各参加者集合の勝者を事前計算し、同じ精算を高速化。既存の精算モジュール自体は変更せず、全終端を別の実カード精算と照合しています。

参考一次資料：[Lanctot et al., Monte Carlo Sampling for Regret Minimization in Extensive Games (2009)](https://proceedings.neurips.cc/paper/2009/hash/00411460f7c92d2124a67ea0f4cb5f85-Abstract.html)。標本化更新の期待値とCFRとの関係を検討する根拠として使用しました。**多人数で一般的なNash均衡への収束保証が得られるとは扱いません。** 第三者のソルバーコードやレンジ・頻度を取り込んでいません。

## 学習とチェックポイント

training seed **120101**、**100,000反復**。1,000／10,000／100,000反復の平均戦略、各席各クラスの観測数、標本上の累積正後悔指標、経過時間を保存しました。未観測クラスは`null`で、Fold100%ではありません。計算内部だけの探索用既定値は50/50で、アプリの推奨には使いません。

最終チェックポイントでは全席の169クラスを観測し、最少クラス観測数は**255回**。これは公開履歴に到達した有効標本数ではないので、各局面の頻度精度を保証しません。1,000反復時点には未観測クラスがあります。

保存方策は分母1,000,000の整数に量子化し、**量子化後の方策を評価**します。記録の小数桁数は戦略精度ではありません。gzip+base64はファイル圧縮のためであり、頻度を隠してGTOとして使うものではありません。再現用候補には戦略配列がありますが、ブラウザ向けレポートから取り除いています。チェックポイントは方策の記録であり、全累積後悔値を保存する学習再開用ファイルではありません。

訓練標本の正のcounterfactual regret指標の9人中最大値は約6.036→4.496→2.019 BB/反復へ低下しましたが、これは標本上の指標であり、真の後悔値の信頼上限・Nash誤差ではありません。停止回数は事前に100,000と固定し、最終テストの成績でチェックポイントを選び直していません。

実測の学習・応答作成・最終評価は約60.3秒、最大RSS約357.9MiB（Node24、Linux、機器依存）。独立Python検証と検証時の再評価は別の追加時間です。詳細は `solver/data/mtt10-mccfr-validation.json`。

## 応答候補の作成と未使用配札による評価

1. 最終平均方策を固定。
2. 別seed **120201** の**100,000配札**で、9人それぞれの各情報集合のFold／参加のcounterfactual利得係数を推定し、大きい方を選ぶ純粋な応答候補を作成。
3. さらに未使用の **120401／120402／120403**、**各10,000配札**で、元の方策と9人の一方的な逸脱を対にして評価。両方に同じ配札・ボードを使い、その差を標本化。

各人が1度しか行動しないので、候補作成用の有限経験分布の169クラス方策の範囲では、各情報集合の2アクションを別々に最大化できます。**ただし、これが通常デッキの真の最適応答とは限りません。** 稀な履歴やクラスの推定誤差で、候補の成績が元の方策を下回ることもあります。

最初のpilotでは応答候補作成に10,000標本、評価seed120301〜120303を使用し、候補が悪化する問題を観測したため、応答候補作成を100,000標本へ変更しました。この判断に使用したpilot seedは最終評価から外しました。最終テストseedは変更後に固定し、その結果による追加選択・調整はしていません。

単にseed番号を分けるだけでなく、各席のホールカードを非順序化し、ボードも並べ替えた**同一の物理配札＋ボード**を正規化してフェーズ間の一致を検査します。独立Pythonでも **230,000組（学習10万＋応答10万＋評価3万）**を再生成し、フェーズ間重複0、正規化台帳のSHA256一致を確認しました。同じクラスや部分的なカードの重なりは合法で、データ漏洩とは区別します。同一フェーズでの偶然の再抽選を拒否して分布を変えることもしません。今回は全組が異なりました。

## 誤差・攻略可能性についての表示ルール

各seedで9人それぞれについて、固定された逸脱方策の平均改善幅、対差の標準誤差、Hoeffding区間を保存します。利得差は[-90,90]BBの範囲に収まるため、9人同時95%の半幅は `180*sqrt(log(18/.05)/(2N))`。N=10,000で **約3.08796BB** と広い区間です。負の推定値も0に丸めず記録します。

この区間は理想的な独立一様抽選を仮定します。Mulberry32という決定論的PRNGが真のIIDである証明ではありません。各seedごとの区間であり、3seed全体・全情報集合・各ハンドの同時95%保証ではありません。

**重要：これは選んだ逸脱方策の成績の区間であり、真の最適応答の利得改善の上限ではありません。** 候補の平均改善が小さい、または負でも、均衡に近いことの証明になりません。正の改善を再現できれば攻略の証拠になりますが、未発見のより強い応答は残り得ます。NashConvやε-Nashの保証値として表示しません。`fullDeckBestResponseUpperBound=null`、`nashConvergenceVerified=false`です。

## 独立検証

`tools/check-mtt10-mccfr.py` はJSのゲーム・評価・精算・更新を呼ばず、以下を別実装します。

- 9人の公開木と全履歴・合法額を再構築。
- 別の整数PRNGとカード除去処理、21個の5枚部分集合による順位、0.5BB層の精算。
- 独立seed120901で32反復の標準MCCFR更新。全後悔値・平均方策の和・観測数を照合。最大後悔更新差 **約1.78e-15**（許容1e-9）。平均の量子化誤差も検査。
- 独立seed120902で32配札の応答候補作成を照合。
- 最終テスト3seedの各128配札、合計384配札で平均利得・逸脱値・対差・標準誤差を別計算。平均改善幅の差は今回0（許容1e-9BB）。
- 全230,000配札のフェーズ分離を再生成・照合。

さらにJSの検証段階で最終評価の全30,000配札を再計算します。全10万反復の更新や全10万配札の応答探索をPythonで独立再学習したわけではありません。小規模での更新の正確さと、保存候補の計算結果の再現性を検証したものです。標本誤差と、多人数の収束保証の欠如は残ります。

## アプリと既存機能

設定 → 『v1.2 MCCFR学習の検証結果』に学習数、配札分離、チェックポイント、9人別の固定逸脱方策の成績と参考区間を表示します。**新しい推奨頻度・ハンド別EVは表示しません。** データ欠落・条件不一致は未計算で、数値を非表示にします。通常9人10BBの169表は未計算のままです。

30BB独自参考表、HU5〜20BB、v1.0制限モデル、v1.1のショーダウン検証、3者モデル、ポジション最上部・全員Fold初期値・段階表示・サイズ編集・更新検知は維持します。

## 再現

```sh
npm run train:mtt10-mccfr --prefix solver
npm run export:mtt10-mccfr --prefix solver
npm run check:mtt10-mccfr --prefix solver
npm run certify:mtt10-mccfr --prefix solver
npm test --prefix solver
npm run test:browser --prefix solver
POKER_BROWSER=webkit npm run test:browser --prefix solver
```

CIでは保存済み候補に対し、`check:mtt10-mccfr -- --check`と全30,000配札の再評価で同一結果を照合します。再学習は毎回行いません。
