# v1.5 学習レンジ統合

**参考戦略・未収束・GTO未認定。** 表示データの条件・整合性の確認と、GTO精度の認定は別です。

## 使い方

既存の「9人卓MTT」モードでスタックを **10BB** に変更します。ポジションは従来どおり上部、①は全員Foldが初期値です。「相手がオールイン」を選ぶと②にAll-in位置・先行Call位置が現れます。1画面の169ハンドを選ぶとFold／All-in／Callの混合頻度を表示します。通常レイズ用のサイズ入力はこのモデルでは隠します。

30BBは従来の独自参考アクション表、10BBは今回の学習平均頻度です。共通のGTO認証を与えたわけではありません。旧来の既知ボード・小規模配札の計算実験も別モードのまま維持します。

## 出所と再現性

- v1.4の均等重みの旧方式、seed140101、100万反復。改善が確認できなかったLCFR候補は使用しません。
- 同じ現行エンジンで100万反復を再生成し、v1.4比較レポートに保存したsnapshotのSHA256と一致を確認しました。
- 510意思決定履歴×169クラス＝86,190行のうち、非ゼロの累積サンプルRegretが少なくとも片方の行動で存在する85,811行を表示し、379行を保守的に非表示にしています。ゼロの行が「確実に一度も訪問されなかった」と証明する判定ではありません。単なるクラス観測回数を、その履歴の有効学習の証拠にはしません。
- 学習平均には序盤の探索方策も含まれます。高いAll-in頻度に小さなFold頻度が残ることがあります。任意の純粋戦略へ丸めたり、強い手から未学習ハンドを補完したりしません。
- `solver/data/mtt10-learned.json` が配布データ、`mtt10-learned-manifest.json` がschema・版・モデル・seed・回数・サイズ・SHA256のmanifestです。

```sh
npm run export:mtt10-learned --prefix solver
npm run check:mtt10-learned --prefix solver
npm test --prefix solver
```

再生成は約98秒でした（この環境・機器依存）。既存v1.4比較結果・学習源コードをそのまま維持し、再生成のsnapshotを照合してから配布用に抽出します。CIはmanifest整合性、比較レポートとの結び付き、全履歴・全行動確率を検査します。全100万反復の再生成は上記exportコマンドで行います。v1.4の端末内checkpointを自動で配布データに置き換えることはありません。

## 表示条件と履歴

9人・全員強制ベット前10BB、SB0.5BB／BB1BB／BBアンティ1BB。52枚の非復元配札・未知ボード、Chip EV、ICM・レーキ・バウンティなし。Fold／All-in／Call、各人1回行動するモデルです。BBのライブ上限は9BB、他席は10BBです。

全員のスタック、人数、アンティなど実効的なモデル条件が完全一致する場合だけ表示します。通常Open・Limp・3bet・4bet・ポストフロップベットは未対応です。これらをJamやCallへ読み替えません。通常Openサイズの設定値はFold/Jam/Callモデルに存在しないため使用せず、30BBの入力を流用しません。

内部APIは全510意思決定履歴に対応し、座席順・行動種別・投入額を検査します。UIでは単独Jam、またはJam＋先行Call1人までを選択できます。選択した人以外の先行者は全員Foldです。先行Call2人以上はUI選択の対象外であり、1人にまとめて解釈しません。

全員Fold後のBBはウォークです。Check/Foldなどの確率を割り当てません。灰色は未学習・更新根拠未確認・未対応・データ読込失敗であり、Foldや0%ではありません。

保存確率は100万分率の整数で保持します。各履歴で合法なのはFold＋Jam、またはFold＋Callの2択です。表示は小数1桁で、片方を丸めて残りを補数とするため合計100.0%になります。元の保存確率を変更する処理ではありません。

## EV・Exploitability・検証状態

表示EVはv1.4の独立評価配札5,000組で求めた**位置別・配札前・全履歴平均の損益（BB/dealt hand）**です。選択ハンドや選択履歴に条件付けたEVではありません。ハンド別EVは未算出として表示します。

真のExploitabilityと厳密Best Response上限は未算出です。表示する近似逸脱候補の改善幅・SE・Hoeffding参考区間は、固定候補を別配札で評価した診断です。真の最適応答でも精度保証の上限でもありません。負の改善幅も残し、0へ丸めて均衡の証拠にしません。区間は各family内・理想的な独立一様抽選を仮定し、全局面や全指標の同時保証は主張しません。

検証状態は既存の「改善中」を引き継ぎ、閾値を緩めません。ラベルは常に参考戦略・GTO未認定です。30BBの参考表用レンダラーが要求する `validation.status=verified` を偽装せず、学習参考専用の表示経路で扱います。

## 読込と整合性

大きい学習データは10BBを初めて選んだ時だけ読み込みます。manifestのバージョン・サイズ・SHA256を検査した後、全行と全履歴の構造を検査して表示用snapshotを固定します。digestは保存・配信上の破損や版の取り違えの検出であり、外部機関の認証や署名ではありません。

破損・旧版・条件違い・読込失敗時には頻度を非表示にし、30BB表や他のハンドへフォールバックしません。読込待ちに30BBやHUへ戻っても、後から届く10BB結果で画面を上書きしません。従来の更新ボタンとPWA更新処理は維持します。

## 残る課題

学習は未収束です。近似応答探索の精度不足、多人数Nash収束保証なし、169クラス制約、厳密full-deck BR上限未確認というv1.4の限界が残ります。ハンド別・履歴別EV、複数の先行Callを編集できるUI、通常レイズやポストフロップは未対応です。今回の統合は、学習データを条件付きで確認できるようにする変更です。
