# 30BBリレイズ対応 v0.7

## データの区別

新規のハンド境界・説明はPoker Lab独自の参考戦略です。ソルバー解、近似均衡、
GTOの混合頻度ではありません。EV・最適頻度・勝率・攻略可能性は未計算です。
既存の参考表を使う人同士が均衡になる、という主張もしません。
相手の実際の範囲は個人差が大きいため、タイトな相手やICMの強い局面には流用しません。
他社の有料・無料レンジ表、画像、頻度データは転載していません。

計算した数値は、ベットの合計／追加額、ポット、残りチップ、最小レイズ、
未コール分の返却、169クラスの分類と6/4/12コンボの集計です。
これらの正しい計算と、選んだハンド境界の戦略的最適性は別です。

## 対応する履歴

| シナリオ | 自分の役割 | 選べる相手 | 表 |
|---|---|---|---|
| 自分のOpen → 3-bet | オープナー | 後ろの3-bettor | 36組のFold / Call / 4-bet14BB / 4-bet All-in |
| 自分の3-bet → 4-bet14BB | 3-bettor | 自分より前のオープナー | 36組のFold / Call / 5-bet All-in |
| 自分の3-bet → 4-bet All-in | 3-bettor | 自分より前のオープナー | 36組のFold / Call。もうレイズはしない |
| 未参加 → Open + 3-bet | 未参加者 | オープナー < 3-bettor < 自分 | 位置は指定できるが参考表は未対応 |

位置順は UTG → UTG+1 → MP → LJ → HJ → CO → BTN → SB → BB。
BBは最初のオープナーにしません。オープナー＝3-bettorや、まだ参加していない人へ
オープナー用の4-bet表を表示することはありません。
他の7人は全員Foldとし、コールドコール、スクイーズ、マルチウェイ続行を扱いません。

### 履歴対象外

全169手を、先のアクションを採用する手／履歴対象外に分類します。
自分がオープナーなら既存オープン表のRaise集合、自分が3-bettorなら
既存対オープン表の3-bet集合に属する手だけを続行判断へ進めます。
それ以外は暗いセルと「履歴対象外」を表示します。FoldやGTO頻度0%ではありません。
実際に基本表外の手で参加した場合の応答は、今回の表の適用外です。

## 条件・チップ計算

- NLHE、9人卓、全員30BBは強制ベット**支払い前**。SB0.5、BB1、BBアンティ1。
- アンティはデッドマネー。BBのライブベット上限は29BB、他は30BB。
- オープン合計2BB、SBのみ2.5BB。
- 3-betはIP合計6BB、SB/BB合計7BB、BB対SBは合計8BB。
- 非オールイン4-betは合計14BB。追加14BBではない。オープナーの残りは16BB。
- ジャムは本人のライブ上限まで。BBの5-betは合計29BB、アンティ込みの支出は30BB。
- 全員Chip EV志向、レーキ0、ICM・バウンティなし。ポストフロップ戦略は未実装。

例：BTN2BB → BB7BBで、判断前ポットは10.5BB。BTNのCall追加5BB、
14BBへの4-bet追加12BB、30BBジャム追加28BBです。
BTN30BBジャムにBBがCallする場合、BBは合計29BBまでしか出せず、
BTNへ1BB返却。最終ポットは59.5BBです。
SB2.5BB → BB8BBでは最小4-bet合計13.5BBなので、14BBは合法です。
SBとBBが上限まで出した場合、返却後のポットは59BBです。

最小レイズの基準は前回のフルレイズ増分です。
参考：[Poker TDA 2026 Rules, Rule45](https://www.pokertda.com/view-poker-tda-rules/)
これはベットの合法性の参照であり、下のハンド境界の根拠ではありません。
Call欄の単純な必要エクイティは将来のベットやエクイティ実現率を無視します。
UIではEV・勝率と混同しないよう、ベット額とポットを優先して表示します。

## 独自の続行設計

早いオープナー＝UTG/UTG+1/MP、中間＝LJ/HJ、後ろ＝CO/BTN/SB。
強いカード・ペアを優先し、遅い位置とブラインドの対戦では参加範囲を広げる設計です。
以下はEVゼロの境界を計算したものではなく、初版の明示的な判断基準です。
強い相手範囲に対する過剰なコミットを避ける一方、非常に積極的な相手には
Foldが多すぎる可能性があります。相手ごとの最適調整は未検証です。

### 自分のOpen → 3-bet

AA/KKは合計14BBの価値4-betへ配置します。
相手の5-betジャムにはCallする計画の枝ですが、AA/KKの最適な配分を意味しません。
30BBでのコミットを明確にするため、残りの強い手の一部を直接All-inにします。
相手の小さいレイズに対するセットマインだけを理由に、小ペアを大量にCallしません。

| オープナー・3-bettor | 直接4-bet All-in | Call |
|---|---|---|
| 早い位置・任意 | AKs AKo | QQ JJ AQs |
| 中間・ブラインド | QQ AKs AKo | JJ TT AQs AJs KQs AQo |
| 中間・ブラインド以外 | QQ AKs AKo | JJ TT AQs KQs |
| 後ろ・ブラインド | QQ JJ AKs AKo AQs | TT 99 88 AJs ATs KQs KJs QJs AQo |
| 後ろ・ブラインド以外 | QQ AKs AKo | JJ TT 99 AQs AJs KQs AQo |

これらは先のRaise集合との共通部分だけです。残りの履歴対象手はFold。
AA/KKを小さい4-bet、AK/QQ等をジャムへ分けるため、サイズが手の強さの情報を
漏らし得ます。バランスされたGTO設計ではなく、学習用の簡略化です。
混合やトラップの最適化は将来の別データとして扱います。

### 自分の3-bet → 非オールイン4-bet14BB

AA/KKを5-bet All-in。QQ/AKs/AKoはCallへ配置します。
後ろのオープナー対ブラインドの3-bettorではJJ/AQsもCall候補とします。
いずれも先の3-bet集合との共通部分だけで、残りはFoldです。
小さい4-betの後は低SPRになるため、Callは単純なセット狙いではありません。
ポストフロップでの具体的な続行計画は今回の表では提供していません。

### 自分の3-bet → 4-bet All-in30BB

- 早いオープナー：KK+ AKsをCall候補。
- 中間：QQ+ AKs AKoをCall候補。
- 後ろ：JJ+ AQs+ AKoをCall候補。

先の3-bet集合と交差し、残りはFold。オールインに対する5-betは表示しません。
早い位置へ特に絞る保守的な設計で、相手のジャムをAK/QQなどが広く占めるなら
Foldしすぎる可能性があります。相手の範囲を使ったCall EVは未計算です。
相手の参考オープン表・4-bet表から推定した自動的な最適反応ではありません。

## 混合表示の土台

`app/range-view.js` は次の二種類を区別します。

- `{kind:'reference', action:'4-bet'}`：単色の基本推奨。100%と変換しない。
- `{kind:'computed', frequencies:{...}, provenance:{...}}`：割合は0〜1。
  合計1、非負有限、既知アクション、method/modelId/sourceと検証スコープが必要。

計算データはセルを複数色で分け、詳細に割合とモデル限定の出典を表示できます。
この入力チェックは数値形式の検査であり、数学的証明の代わりではありません。
実データの登録前には、その計算・検証・利用権利の確認が別途必要です。
現在の30BB参考データには混合割合を付けていません。
70/30等はテスト専用の架空描画例だけで、配布戦略データには含めていません。
