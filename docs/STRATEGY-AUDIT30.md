# 30BB参考戦略の監査 v0.8 — 2026-11-03

## 結論と今回の変更

既存のオープン・対オープン・対3bet・対4betは、依然として独自参考戦略です。
数学的に検証済みの9人卓GTOにはなっていません。
相手範囲や将来のベットを特定できないため、**既存の無条件のハンド境界は変更していません**。
Axs、小ペア、KQo、KJs、QJsを生のエクイティだけで入れ替えることもしません。

改善したのは、4bet All-inに対し「相手範囲を仮定してCall/Foldを計算・比較する機能」と、
各参考表の限界の表示です。従来表は初期選択のまま保ち、計算モデルは利用者が選びます。
モデル選択時は従来のCall/Foldから計算結果へ切り替わり、相手範囲・エクイティ・必要値・
条件付きCall EVを表示します。全モデル、全位置の変更一覧は
[practical-audit-report.json](../solver/data/practical-audit-report.json) に保存しています。

## 対象条件

全員30BBは支払い前、9人卓、SB0.5/BB1/BBアンティ1、Chip EV、レーキ0、ICMなし。
通常Open2/SB2.5、3bet6/7/SB対BB8、非All-in4bet14。
BBはアンティ支払い後のライブ上限29BB。他は30BBです。
他7人は全員Fold。実際のフォールドが持つカード情報は推定せず、未知カードとして扱います。

参照戦略は8オープン表、36対オープン表、36対3bet表、36対4bet14BB表、
36対4bet All-in表。各169クラスを分類し、履歴対象外はFoldと区別します。

## 参考表の点検結果

| 項目 | 発見・評価 | 対応 |
|---|---|---|
| オープン | UTGからBTNまで採用集合は入れ子で拡大し、プレミアムの欠落はない | 構造は確認。最適な広さの証明ではなく、境界は維持 |
| Axs | UTGのA5s以上、後続位置で低いAxsを追加。低Aのブロッカーには理屈があるが、その境界のEVは未計算 | A4s/A5s等を新しい頻度で埋めない |
| 小ペア | 前は55+、順に44/33/22を追加。対3betでは小ペアを絞る | 30BBのセット狙いの利益は、相手・将来の支払額なしには証明できない。維持 |
| KQo | 早いOpenには採用するが、対3betではFoldへ絞る | Openと再レイズへの続行条件は別。生の勝率でCallへ変更しない |
| KJs/QJs | 後ろの位置やブラインドで参加候補が増える | キッカー負け、位置、実現率を未計算。原則比較だけで境界を変更しない |
| 対オープン | 36組の行動順、サイズ、BBの追加Call・単純オッズは整合 | SBの3bet/Fold簡略化や、IPのCall幅は戦略的に未証明 |
| SB Limp | 強い手をRaiseに寄せるため、Limpの上限が読まれやすい | 画面にも警告。根拠のないトラップ頻度を追加しない |
| 対3bet | AA/KKを14BB、AK等をジャムへ分けるためサイズから情報が漏れる | 画面にも警告。均衡戦略と表示しない |
| 非All-in4betへのCall | QQ/AK等のCallが配置されるが、後続ベットが残る | Call EVを単純なショーダウン期待値で代用しない。境界は維持 |
| All-inへのCall | 従来の位置別集合は、相手範囲によって正負が逆転する | 相手固定の条件付き計算で比較可能にした |

さらに、相手が機械的に当アプリの4betジャム枝を使うと仮定した診断では、
全36組で従来のCall/Foldと固定相手への最適反応に差がありました。
早い位置のジャムにAA/KKを含めないため、QQをFoldする従来応答と整合しません。
これは「参考表同士が均衡ではない」反例です。到達確率や全ツリーの最適反応を
計算していないので、全ゲームのNash gap・攻略可能性の数値とは呼びません。
この自己対戦仮定を、実際の相手のレンジとしてUIに自動適用していません。

## 相手固定モデルと計算

UIで選べる仮定は次の3つです。

- QQ+ AKs AKo
- KK+ AKs
- JJ+ AQs+ AKo

どれも「30BBならこの範囲でジャムするのが正しい」という意味ではありません。
各モデルの合法な物理カード組を一様に重み付けし、自分のカードと重複する組は除外します。
ハンドクラスを等確率にしたり、ブロッカーを無視した6/4/12重みをそのまま使ったりしません。
例えばQQ+AKに対してAKsを持つ場合、相手の合法組は34組ではなく21組です。

既存の正確な列挙行列は、各対戦で残り48枚からの全1,712,304ボードを対象とします。
SHA256: `9f2a641fbdfde0659533e68e3a38cafde4924d14143f9583978861d3591df40d`。
勝ちを2、引分を1とする整数カウントから範囲エクイティを集計します。

この判断点でFold=0とした追加Call EVは、
`エクイティ × 返却精算後のCall後ポット − 追加Call額`。
過去に出したOpen/3bet/アンティはサンクコストです。
整数カウントと0.5BB単位の整数をBigIntで比較してCall/Foldを決め、表示だけを丸めます。
従って小さなプラスを表示丸めで判定し直しません。同価値ならその旨をデータに記録します。

All-in後にベットは残らず、相手が1人という仮定なので、この限定したCall/Fold比較では
エクイティから追加Chip EVを算出できます。通常のOpen、3bet、4bet14BBの利益や、
トーナメントの賞金EVを証明したものではありません。先の3bet採用は参考表のままです。

### 修正前後の具体例（モデル選択時だけ）

| 局面・相手の仮定 | 手 | 従来参考 | 条件付き計算 | 理由・追加Call EV |
|---|---|---|---|---|
| UTG Open → BTN3bet → UTG jam、QQ+AK | QQ | Fold | Call | エクイティ40.207% > 必要38.400%、+1.129BB |
| 同上 | AKo | Fold | Call | 38.824% > 38.400%、+0.265BB。仮定に敏感な境界 |
| BTN Open → BB3bet → BTN jam、QQ+AK | AQs | Call | Fold | 28.607% < 必要36.975%、−4.979BB |
| 同上 | JJ | Call | Fold | 36.190% < 36.975%、−0.467BB |
| SB Open → BB3bet → SB jam、QQ+AK | JJ | Call | Call | 同じエクイティでも必要35.593%となり、価格が異なる |
| UTG Open → BTN3bet → UTG jam、KK+AKs | QQ | Fold | Fold | エクイティ27.182%。上のQQのCallを一律には勧められない |

BBのアンティ・ライブ上限29BB・未コール分返却を含めます。
BTN対BBの最終ポット59.5BB、追加22BB。SB対BBは最終59BB、追加21BB。
これらの違いを無視して「JJは必ずCall/Fold」とまとめません。

## 実施した検査

- 3仮定×36組＝108比較、各169クラス。履歴対象外は条件付き計算でも維持。
- 元の8+36+36+36+36表の分類・アクション順・チップ台帳の既存テストを回帰。
- 全169クラスで集計を列挙行列と照合。物理カードを直接除外する別処理で重みを照合。
- 条件付きCall/Foldの符号を整数比較で確認。仮定変更・位置ごとの価格差もテスト。
- native行列とは別のJavaScript評価器と物理カード抽選で、10ケース各6万、計60万試行を照合。
  最大差は約0.508パーセントポイント。これは再現可能なMCの健全性確認であり、
  最適アクションの証明や、新しい行列全要素の独立全列挙ではありません。
- モバイルで比較モデル切替、数値とアクションの区別、失敗時の未対応表示、HU等を回帰。
