# v1.4 MCCFR学習改善と比較実験

**GTO精度は未確認。未収束の戦略を推奨レンジに公開しない。**

9人、全員10BB（強制ベット前）、SB0.5・BB1・BBアンティ1BB。Chip EV、ICM・レーキなし。v1.2/v1.3のFold / All-in / Callモデル、カード除外、オーバーコール、サイドポット・未コール返却を維持する。

## 原因分析

1. v1.3の標準Regret更新と条件付き平均には、今回の「各席1回だけ行動する」ゲームにおける明らかな式の誤りは見つからなかった。相手による公開履歴への到達確率をRegretに掛け、本人の先行行動確率は1として平均する。自分の方策平均を相手の到達確率で重み付けしてはいけない。
2. 86,190行を1万の同時配札で応答学習していた。各クラスの観測は限られ、低到達率の履歴では有効標本がさらに不足する。v1.3の応答候補がholdoutで全席マイナスだったことは、十分なBR探索ができていない兆候。低い改善幅をGTOの証拠にしてはいけない。
3. 全履歴×169クラスの等重みの戦略変化は、ほぼ到達しない履歴も含む。大きな変化が実戦EVの同じ大きさの変化を意味するわけではない。ただし、変化が大きいという従来基準を隠したり緩めたりせず維持する。
4. 実装は配札ごとに多くのベクトルを確保し、評価のたびに全86,190行の確率検査を繰り返していた。新しい経路ではバッファを再利用し、方策の検査は評価バッチの入口で1回だけ行う。

## 候補方式と正当性

候補はLinear CFR (LCFR)の実験。反復tのサンプルRegretと平均戦略の両方にtの重みを掛け、序盤の影響を下げる。配札の分布は以前と同じ、52枚非復元のjoint chance sampling。サンプリング分布と対象分布が一致するので追加のimportance比は1。各反復の方策を先に固定してから全行動を評価し、同時に更新する。

出典：[Brown & Sandholm, 2019, Discounted Regret Minimization](https://ojs.aaai.org/index.php/AAAI/article/view/4007)。この方法を採用しただけで9人のNash収束保証が得られるわけではない。CFR+のノイズ付きRegretを0でクリップする方式への置換は行わない。

旧版と比較するRegretは、両方式とも**重みを付ける前の瞬間Regretを累積した正部分 / 反復数**。LCFRの内部の重み付きRegret自体と区別する。これは標本診断であり、真のBR上限ではない。

新しいkernelは既存のpublic treeと精算の定数を利用する。7枚評価器を維持し、カードスコアを基数15の整数に符号化して同じ辞書順で比較する。全終端・同点・マルチウェイの利得、旧方式の学習経路と平均戦略、逸脱評価を旧実装と照合する。

## 事前固定した比較計画

- 学習seedは140101 / 140102の2本。各seedで旧方式とLCFRに同じ配札列を与える（paired comparison）。seed間は別系列。
- 1万・10万・100万反復で平均戦略の変化・Regret・EV・固定した近似応答候補の改善幅を記録。
- 各checkpointで別seedの1万配札で応答候補を作り、さらに2千配札の別系列で採用可否を選択し、未使用5千配札で最終評価。各modeで共通の配札を使用する。
- 選択版の応答は、各席の改善幅のHoeffding下限が選択標本上で正の場合だけ採用。それ以外は基準方策を維持。**採用なしの0は収束の証拠ではない**。従来型の応答候補も採用選択せず最終評価し、負の結果もそのまま残す。
- Paired EV差・固定逸脱改善幅の差、標準誤差、Hoeffding区間を計算。各記載family内での区間であり、全seed・全checkpoint・全指標をまとめた同時被覆は主張しない。疑似乱数の別seedは独立性の数学的証明ではない。
- 固定近似応答の改善幅の正部分の和は診断値。真のExploitability、NashConv、信頼下限ではない。2人零和用のNashConv/2を使わず、真の値と上限はnullに保つ。

`mtt10-learning-comparison.json`に全数値・条件・seed・平均戦略snapshotのSHA256・源コードSHA256・計算資源を保存する。全平均戦略をこのレポートから配布することはしない。全学習の再実行で再現できる。CIではレポートの源コード・固定実験計画・旧方式の数値一致・基準の維持を照合し、短い回帰テストで学習式と保存・再開を検証する。

v1.3の認定基準は変更しない。比較レポートは「改善中」で、候補方式から「検証済み」は返さない。今回の診断だけでGTOへの収束改善が実証されたとは扱わない。UIとCLIの初期方式は旧方式のまま。LCFRは明示的に選ぶ研究用候補。

## 実行と途中保存

```sh
npm test --prefix solver
npm run compare:mtt10-learning --prefix solver
npm run check:mtt10-learning --prefix solver
npm run train:mtt10-learning --prefix solver -- --mode linear --seed 140501 --iterations 10000 --checkpoint /tmp/poker-checkpoint.json
npm run train:mtt10-learning --prefix solver -- --resume --iterations 100000 --checkpoint /tmp/poker-checkpoint.json
```

CLIは1万反復ごとに一時ファイルへ書いてrename。SIGINT/SIGTERM時も現在の小区間の後に保存する。`--resume`時は保存されたseed・modeを使用する。

再開データはPRNGの内部word、反復数、正負を保った累積Regret、診断用の無重みRegret、平均戦略の分子・分母、観測数をFloat64の精度のまま保存する。単なる丸め済み平均戦略からは再開しない。schema/model/seed/mode、配列長・有限性・訪問合計を検査し、SHA256付きバイナリpacket（CLIはgzip可）で破損を検出する。SHAは破損検出であり署名ではない。

## iPhoneの実行経路

設定から「v1.4 学習方式の比較・途中保存」を開く。計算専用Web Workerで1slice最大64反復か12msまで処理し、イベントループへ戻る。進捗通知は間引く。主画面のスレッドで学習ループ・JSON圧縮を実行しない。

1回1万反復の明示操作。停止・保存・再開可能。チェックポイントはWorkerでバイナリ化・SHA256計算し、ArrayBufferを転送してIndexedDBへ非同期保存する。WebKitで保存待ちが完了しなかったストリーム圧縮・Blob経路はWorkerから外し、CLIのみgzip圧縮を利用する。画面非表示時にも停止して保存を試みる。タブがOSから突然破棄された場合や、保存権限・容量がない場合の保存は保証できない。保存成功の表示を確認する。計算を再開しても推奨レンジは書き換えない。

## 計測と限界

学習は配札・終端利得・順方向・逆方向の時間を分ける。同じ1万反復の旧実装と最適化した均等重み実装を3回、順序を交互にして測り、平均戦略のSHA256一致を確認する。時間は機器と負荷に依存する。

残る限界：2学習seedのみ、限られた応答探索、広い区間、169クラス方策制限、多人数のNash保証なし、条件一致の公開レンジとの独立検証未達。現在のFold/Jam/Callモデル外の通常レイズやポストフロップ等へ結果を外挿しない。
