# iPhoneホーム画面での更新

## 動作

起動時に、HTMLに埋めた現在版と同じ場所の `version.json` を比較します。
確認には `cache: no-store` と時刻クエリを使います。
新しいrevisionがあれば上部に通知します。自動再読み込みはせず、選択したハンドを保ちます。
「更新を確認」は手動確認、「最新版を読み込む」は通信確認後の再読み込みです。
後者は `refresh` と版の `v` クエリを付け、HTTPキャッシュとは別URLでHTMLを取得します。

`pageshow.persisted` で凍結・履歴からの復元を確認します。
`visibilitychange` とfocusでアプリ復帰にも対応し、頻繁なイベントは30秒で間引きます。
通信復帰のonlineと手動操作はこの間引きをしません。同時要求はまとめます。
8秒で確認要求を中断し、通信失敗・不正な応答・404では表示中のアプリを保持して再試行できます。
取得済みの新しい版より古いCDN応答は、通知を取り消したりダウングレードしたりしません。

Service Workerは導入しません。ブラウザ全体のキャッシュ削除、個人データ削除、
別アプリのキャッシュ操作はありません。表示済みページの動作は保ちますが、
圏外での新規起動・オフライン保存を保証する機能ではありません。

## 最初の一度と限界

このコードを含まない旧版は、更新検知自体を実行できません。
旧版の「最新版を読み込む」やキャッシュを避けたリンクで、最初にv0.6以降を読み込む必要があります。
以後、その版がキャッシュから復元されてもリリース確認を実行します。
iOSによるプロセス停止中は実行できず、起動・復帰後に確認します。
GitHub Pagesの配信反映や通信状況により、通知は公開直後に必ず届くものではありません。

## リリース手順

1. `version.json` の `revision` を単調増加させ、versionと一意のbuildを指定する。
2. `index.html` の `appRelease` に同じ値を埋め込み、全scriptの `?v=` をbuildへ変更する。
3. manifest・HTML・JSを一つのGitコミットで保存する。
4. `npm test --prefix solver` とブラウザ操作テストを実行する。
5. Pages配信後にHTMLと `version.json` を確認する。

HTMLとmanifestとscriptの版の一致はテストで検査します。
`app/updates.js` はレンジデータから独立しています。
リモートmanifestにナビゲーション先URLを渡さず、現在の同一オリジン・パスだけを再取得します。

## モバイル操作

ポジションはタップしやすい幅で折り返し、フォームは16px以上にします。
169セルの比較表は13列を維持し、選択ハンドと推奨を画面上部へ固定表示します。
「理由を見る」は同一画面の説明へ移動し、設定した視覚効果低減にも従います。
セルは選択状態と参考アクションを読み上げに渡します。
対オープンは状況の直下から相手を選び、8ポジションのオープン表・36応答表を使います。
戦略ルール自体はv0.5の独自参考設計を維持しています。新しいGTO頻度は作っていません。

## 検証範囲

Nodeで版検証・更新検出・間引き・同時要求・通信失敗・タイムアウト・再試行・
同一オリジン再読み込み・配信ファイルの版一致を検査します。
PlaywrightではChromiumとWebKit、それぞれ375/390/430pxで既存HU、小規模モデル、
全36応答の選択、選択ハンド表示、キャッシュ復元イベントでの新しい版の検知、
失敗時の画面保持、更新ボタン、更新スクリプト欠落時の既存ボタンを検査します。
WebKitもiPhone実機そのものではないため、ホーム画面独立アプリの実機検証は別途必要です。
