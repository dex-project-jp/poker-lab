# v1.0：9人10BB計算エンジンの第一段階

**通常の9人卓MTTのGTOは未計算です。** 今回は9人全員が意思決定する有限ゲームを独立に計算し、各人の最適応答で数値的な近似均衡の範囲を確認しました。既存参考レンジを計算結果として転用していません。実戦でこの実験の頻度を使用しないでください。

## 条件とスタックの意味

共通条件はNLHE、9人、強制ベット前の全員10BB、SB 0.5BB、BB 1BB、BBアンティ1BB、Chip EV、ICM・レーキ・バウンティなしです。順序はUTG、UTG+1、UTG+2（画面MP）、LJ、HJ、CO、BTN、SB、BB。

開始ポット2.5BB。SBの残り9.5BB、BBの残り8BB。他の7人は10BB。アンティはデッドマネーでライブベットに数えません。BBのライブ投入上限は9BB、他の人は10BBです。BBが最後に単独で残る場合はウォークであり、Checkを選ぶ局面ではありません。

- `mtt10-game.js`：9人の状態遷移、配札、情報集合、有限木。
- `multiplayer-pots.js`：人数に依存しない精算、同点分配、サイドポット、未コール返却。実カードのショーダウンは全員の手札（Fold済み含む）とボードの重複を拒否。
- `multiplayer-solver.js`：任意人数のCFR+探索、評価、情報集合の最適応答。既存HU／3人ソルバーとは別モジュール。
- `mtt10-view.js`：計算条件と証明情報を照合し、対応する履歴だけを画面に渡す。

ライブ投入を昇順の層に分割し、各層の参加額を確保した非Fold者だけを勝者候補にします。唯一の拠出者しかいない上層は返却します。デッドアンティは有効な参加者の主ポットに加えます。合計利得は0、配分＋返却は全投入に等しいことを検証します。

例：UTGが10BB Jam、他はFold、BBがライブ9BBまでCallすると、現在ポット12.5BB、追加Call8BB、未コール1BB返却、争うポット19.5BB。UTG+1も10BB Call済みなら現在22.5BB、BB追加8BB、争う総ポット30.5BBです（SBがFoldした0.5BB込み）。先行CallerがSBなどの場合は強制ベットを重ねて加算せず、その位置のライブ額で計算します。BBが参加できない上層は他の2人のサイドポットになります。

## 実際に計算した制限ゲーム

これは通常のプリフロップ配札を忠実に縮小した近似ではなく、エンジン・独立検証器を検証する意図的に特殊なゲームです。

1. ボード `2c 2d 2h 3c 3d` を**ベット前から全員が知る**。
2. 基準配札は各席順にAA/KK/QQ/JJ/TT/99/88/77/66。10世界のうち世界w=0..8では、その席wのペアを55に置き換える。世界9は基準のまま。
3. 世界0は9/18、世界1..9は各1/18の確率。18等確率抽選チケットで表現する。世界0を9回数えるが、異なる物理配札として9重計上しない。
4. 各ペアの6スートコンボは等確率。世界内で各席のランクは異なり、ボードとも重ならない。10世界×6^9 = **100,776,960通りの異なる合法配札**。スートによる勝敗順位・合法手・私的情報の確率構造が変わらないため、ランク世界に厳密に集約できる。独立検証では各6コンボの評価と席間・ボードとの非重複を因数分解して確認しており、1億配札を個別列挙したわけではない。
5. 最初のJam前はFold/All-in。Jam後はFold/Callのみ。各人は1回だけ行動し、最大9人のオーバーコールを含めて木を展開する。各人は自分のペアと公開アクション履歴だけを知る。世界番号・他人の私札を情報集合に含めない。
6. 通常Raise、Limp、再レイズ、未知のボード・ポストフロップベットはない。

木は18,378ノード／1,020情報集合／9,198終端。全席が能動的に意思決定するのでHUの利得を足し合わせたモデルではありません。全員に同時に異なるカードを割り当て、マルチウェイの勝敗とポットを計算します。通常配札の1326コンボ全てを一様に扱った結果ではありません。各席は固有の基準ペアと55の2種類だけであり、169表の残り167種類をFoldで埋めません。

## 手法の比較と採用理由

| 手法 | 採用判断・限界 |
| --- | --- |
| 既存HUのLP／minimax | HUゼロ和の双対性による保証を9人へ移植できない。既存HU機能のみに保持。 |
| CFR+ | 有限ゲームの探索として一般人数に拡張。多人数ではNash均衡への収束を保証しないため、反復数や後悔値のみで合格にしない。 |
| MCCFR・配札／ボードサンプリング | 将来のフル配札で必要になる候補。分散・稀な局面・最適応答の過小評価を別途扱う必要があり、今回の証明に使用しない。 |
| 多人数の非凸最適化（QCQP等） | 研究上の候補だが計算規模・大域性・実装依存が増える。現時点で商用ソルバーや有料サービスは使用しない。 |
| 固定した他8人に対する各人のBR | 今回の合否判定。9人全員の一方的利得改善を独立計算。全員が一度しか行動しない木なので、各情報集合の単体制約LPで全純粋／混合逸脱を包含する。将来複数回行動する木ではsequence-formの親子実現確率制約が必要。 |

一次資料：Zinkevich et al., [Regret Minimization in Games with Incomplete Information (2007)](https://proceedings.neurips.cc/paper/2007/hash/08d98638c6fcd194a4b1e6992063e944-Abstract.html)。Ganzfried, [Multiplayer Equilibrium Computation via Non-Convex Quadratic Programming (2025, updated 2026)](https://arxiv.org/abs/2509.25618)。後者は多人数でCFR／fictitious playに一般的なNash収束保証がない点も論じる。資料は手法の検討に利用し、他社レンジ・画像・頻度・ソルバーコードは取り込んでいない。公開論文へのリンクはデータの再配布ライセンスを意味しない。今回のコード・戦略は本リポジトリで生成。

## 計算結果と合否基準

CFR+を20,000反復。1,000反復ごとに現在戦略と線形平均を評価。選択は20,000反復の線形平均。探索目標1e-5 BB/model-dealt-handは**未達**です。探索は約48.565秒、木構築約117.79ms、peak RSS約224.480MiB、heap約53.270MiB（Node v24.22.1、Linux x64、機器依存）。

公開頻度は分母1,000,000,000の整数重みに丸めた**後**、全員のBRを再計算しています。

- 最大の一方的改善幅 ε = **0.0017566451472367816 BB/モデル配札**。
- 9人分改善幅の和 NashConv = **0.0023342658435256992 BB/モデル配札**。
- Python Fractionの有理数比較で ε ≤ **1/500 BB = 0.002 BB** を確認。この有限モデル内のε近似Nashとしての上限を検証したもので、目標1e-5まで収束したとは表現しない。
- 多人数でNashConvを2で割って『攻略可能性』としない。
- これは配札前の平均的な改善幅であり、各ハンド・到達確率の小さい各局面の条件付き誤差上限ではない。モデル外の実戦での誤差も意味しない。

独立Python検証器はJSの状態遷移・ポット関数を呼ばず、木を再構築し、全終端の0.5BBスライス会計を比較します。別の5枚組合せ評価器でボード上の順位を確認。9人それぞれについてSciPy sparse LPと有理数の厳密BRを照合し、JS評価との許容差1e-9 BBを確認します。ハッシュで候補戦略・ソース・木を固定し、再生成が一致しなければ画面データを出力しません。詳細数値・9人別利得・反復履歴は `solver/data/mtt10-validation.json` に記録。

## 画面・信頼区分

- 通常の『9人MTT』10BBは**未計算**。30BB参考表を流用しない。
- 別モード『9人10BB 計算実験（制限ゲーム・近似）』だけが今回の数値を表示する。
- 対応履歴は全員Foldでの8位置、単独Jamへの36応答、先行Caller1人への84応答、合計128ビュー。計算木にはそれ以上の複数オーバーコールも含まれるが、今回UIでは先行Caller2人以上を選べない。
- BB未オープンはウォーク。各席の2種類以外はモデル対象外。到達確率0の情報集合は頻度・EVを表示しない。
- スタック／アンティ等の条件が一致しない、データ欠落、未対応履歴は未計算。推奨アクション・Fold100%・EVを生成しない。
- 分類は『近似計算』。この小ゲームの改善幅上限の検証済みという意味を、完全MTTの検証済みGTOと混同しない。既存HU検証済み計算／3人制限モデル／30BB独自参考戦略とは独立。

## 次の拡張と未対応

最優先は特殊な配札と既知ボードを外すこと。全1326コンボ・9人の条件付き同時配札・Foldによる情報更新・未知ボードのマルチウェイ評価を接続し、独立した標本とBR評価の誤差を記録する。ペアごとのHU勝率の足し算では代替しない。その後、Open Raise/SB Limp/BB Check/3bet/4betなど複数回の行動を含む木とBRのsequence-form実装へ拡張する。

5〜100BB・異スタック・ICM・バウンティ・キャッシュ・レーキは未計算。ポットモジュールは異スタックを精算できるが、その戦略が解けた意味ではない。フルゲームのNash収束が保証されると見せることなく、段階ごとに実行可能な木・計算資源・独立検証基準を定義する。
