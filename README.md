# Poker Lab

スマホ向けのポーカー学習アプリ。初期画面は**9人卓MTT・30BB・BTN**です。

**30BBの全8ポジションのオープン表と、全36通りの単独オープンへの応答表を使えます。**
UTG / UTG+1 / MP（内部ID UTG+2）/ LJ / HJ / CO / BTN / SBに対応。
各表は169ハンド全てに一つの基本アクションと説明を持ちます。

これは**独自設計の実戦参考戦略であり、検証済みGTOやソルバー計算の混合頻度ではありません。**
根拠のないGTO頻度やEVは表示しません。色は基本推奨アクション、集計の%は採用コンボ比率です。
第三者のレンジ表・画像・頻度データは転載していません。

[実戦表の設計根拠・全ルール・限界・権利整理](docs/PRACTICAL30.md) /
[機械可読の集計](solver/data/practical30-summary.json)

前提は全員30BB、BBアンティ1BB、通常オープン2BB／SB2.5BB、Chip EV志向、レーキ0、ICMなし。
SBはRaise/Limp/Foldを使い、30BBのオープンジャムは今回の基本設計では採用しません。
対オープンでは、単独の先行レイズにFold/Call/3betを提示します。
v0.7は自分のOpenへの3bet、自分の3betへの4bet14BB／All-inにも対応します。
他スタック・別サイズ・コールド4betには表を黙って流用しません。
設計と条件は [30BBリレイズ対応](docs/RERAISES30.md) を参照してください。

既存HUの5〜20BB、3者の制約モデルも学習モードから利用可能です。
数学的に検証した既存データと、今回の独自参考戦略は別の名前空間と表示で扱います。
有料サービスの購入・契約はしていません。

## MCCFR戦略学習（v1.2）

通常52枚から毎反復新しい配札・未知ボードを抽選し、169クラスでFold/Jam/Callを学習するchance-sampled MCCFRを追加。10万反復、別10万配札で応答候補を作成し、さらに未使用3seed×1万配札で評価しました。全23万組のフェーズ間重複0を独立照合。32反復の後悔値更新と小規模な応答・別配札評価も独立Pythonと一致しました。

**均衡収束・通常デッキの攻略可能性上限は未確認です。新しい推奨頻度は169表に公開していません。** 候補の成績の参考区間は約±3.088BBと広く、真の最適応答の上限ではありません。既存機能を保ち、設定から[学習検証画面](mccfr-validation.html)を開けます。

[完全な手法・データ分離・限界・再現方法](docs/MTT10-MCCFR.md) / [検証結果](solver/data/mtt10-mccfr-validation.json)

## 通常デッキ・未知ボード（v1.1）

52枚・1,326コンボ・169クラスから9人に配り、Foldした私札も除外して未知ボードを生成する計算基盤を追加。9人／HU／3人の固定参加を各2万標本計算し、独立Pythonで6万ショーダウン・精算を照合しました。AA対ランダムは厳密行列85.2037%に対し標本85.3425%。理想IID仮定の参考区間は各条件約±1.2131ポイントです。

**新しい実戦GTO頻度は公開していません。** 少数配札のCFR+接続試験は過学習を検出する診断であり、訓練内ε=0を通常デッキの均衡保証とは扱いません。既存レンジは維持し、設定内の[検証結果画面](engine-validation.html)だけに推定エクイティを表示します。

## 9人10BB計算エンジン（v1.0）

**完全な9人卓10BBのGTOは未完成です。** 別モードの計算実験では9人全員がFold/Jam/Callを選択し、最大9人の参加・サイドポット・返却を処理します。既知ボードと特殊な10配札世界だけを解いた近似戦略です。各席2ペアだけを表示し、他167手は未計算のままです。通常MTTの10BB表に流用しません。

20,000反復後、全9人の最適応答を独立Python LPと有理数で検証。最大改善幅0.00175665 BB/モデル配札（上限0.002BB）を確認しましたが、探索目標1e-5BBは未達です。30BB参考表・HU5〜20BB・3者検証モデルは維持します。

## BTN・SB・BBの実計算（v0.4）

**完全な9人卓MTTのGTOではありません。** 学習モードの「検証モデル」では、
AA/KK/QQ/JJだけの配布・開始時から既知の固定ボード・4bet/ポストフロップベットなし
という有限ゲームを実際に解き、3者それぞれの一方的な戦略変更の改善を1e-5 BB/hand以下に検証。
独立したPythonのsequence-form LP、全5,184配布のカード除外、サイドポット会計も照合しています。
169表のうち4ペアのみを表示し、残り165マスをFoldとして埋めません。

[モデルの完全な定義・検証・次の拡張](docs/BTN30-SOLVER.md) / [実測結果](solver/data/btn-mini-validation.json)

### 異なるスタックを有効スタックで扱う条件

今回のHU・アンティなし・レーキなし・Chip EVでは、S=min(SB,BB)が
ショーダウンで争うスタックです。コールされなかった余剰チップは返却するため、
勝利時の純増は+S、敗北時は-S。SBフォールド=-0.5、BBフォールドでSBは+1。
よって同じSの同額スタックと利得・配布確率・均衡が一致します。
異なるスタックの両方向、返却チップの会計式、両ポジションをテストします。
アンティあり・多人数・ICMへはこの同値性を無条件に流用しません。

## 数学と検証

- 52枚から全1,326コンボを列挙。各コンボに対する合法な相手は1,225通り。
  全1,624,350通りの順序付き配り方でカード除外を検査します。
- スート名を置換したゲームは同一なので、169クラスに**厳密に縮約**します。
  6/4/12コンボの重みと各クラス間の合法な組み合わせ数を使います。
  クラスの確率を単純に掛ける方法は使いません。
- 勝率表は各対戦の全C(48,5)=1,712,304ボードの勝利・引分を整数で集計。
  スート置換とプレイヤー交換で47,008対戦へ縮約します。
- MITライセンスの[nuts](https://github.com/ZorigoKH/nuts/tree/bdd02c3a24a1e3ff458944ab5f8fa10ad808ff54)
  の生成コード・整数表を固定して同梱。全表を再計算しバイト単位で比較済みです。
  Poker Lab独自のJS評価器でも6種類の対戦クラスの全スート組み合わせを比較。
- Poker Labの交互更新CFR+と、SciPy/HiGHSによる独立した2つの線形計画問題を比較。
  公開戦略はLP解。CFR+とのEV差・頻度差・全ハンドの最適応答利得を検査します。
- Nash gap = SBの最適応答による改善 + BBの最適応答による改善。
  exploitability = Nash gap / 2。単位は**配られた1ハンド当たりBB**です。
  浮動小数点による近似解であり、誤差ゼロの証明とは扱いません。
- 公開許容Nash gapは1e-10、独立CFR+のNash gapは1e-8 BB/hand以下。
  [検証結果](solver/data/validation-report.json)に実測値・停止条件・履歴を保存します。
- HoldemResourcesの[No Anteチャート](https://www.holdemresources.net/hune)とも
  境界から離れた10ハンドを定性的に比較。簡略チャートから混合頻度は作りません。

### 169クラスに縮約しても攻略可能性を検査できる理由

対戦相手の戦略が全スート置換に対して不変なら、自分の同一クラス内の
各コンボにおける各アクションの条件付き期待値も同一です。
したがってスート別に異なる最適応答を許しても利得は増えず、
169クラスの最適応答検査が1,326コンボでの検査と等価です。
`exact.test.mjs`はこの縮約に必要な相手クラス別の配布数を全1,326コンボで検査します。
特定のスートを偏らせた相手レンジやフロップ後には、この縮約を流用しません。

## 開発用の再実行

利用者のPC操作は不要です。以下は開発・CI用です。

```sh
cd solver
npm test
npm run status:mtt # 数値レンジ未公開を含むMTT対応状況
python -m pip install scipy==1.17.0
npm run solve:lp
npm run solve:range # 全5..20BBの独立LP
npm run check:equities
npm run check:evaluator # 全133,784,560通りの7枚の役を照合
npm run regenerate  # C++20コンパイラ、全対戦再計算
npm run certify    # 既存10BBと厳密勝率表の検証
npm run certify:range # 全16条件の検証・公開データ生成
```

CIはテスト、独立LP、独自JS勝率照合、公開データの再生成・差分検査を実行します。
全表再計算も手動ワークフローで実行可能です。戦略データを手で編集しないでください。

## 拡張境界

`game.js`が配布確率・利得・最適応答を扱い、`nash-iteration.js`が均衡を計算、
`exact-matrix.js`が今回の厳密な縮約表を読みます。`hu10-view.js`は画面の条件照合のみ。
将来の多人数・ベットツリー・ICMにはそれぞれ別のゲームモデルと検証が必要です。
HUのゼロ和最適応答証明を、そのまま9人ゲームの均衡証明には使いません。

第三者コードのライセンスと固定バージョンは[PROVENANCE](solver/vendor/nuts/PROVENANCE.md)を参照。


## iPhoneの更新・操作（v0.6）

- 起動時、ページ復元時、アプリへの復帰時、通信復帰時に `version.json` を確認します。
- 新しい版は画面上部に通知し、学習中の画面を勝手に切り替えません。
- 「最新版を読み込む」は通信確認後、別のURLクエリでHTMLを再取得します。
- 通信失敗では表示中のレンジを保ち、再試行できます。オフライン保存を保証する機能ではありません。
- 更新検知をまだ持たない旧版は、初回だけ最新版を開く必要があります。
- レンジのタップ時は推奨を固定表示し、「理由を見る」で説明へ移動します。
- 対オープンの相手選択は「状況」の直下。行動順に反する相手は選べません。

リリース手順・制約は [docs/UPDATES.md](docs/UPDATES.md) を参照してください。
